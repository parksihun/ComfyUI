# ComfyUI-Manager: 이미지·영상 생성 관리

ComfyUI와 따로 도는 작은 웹 서버입니다. 이 프로그램은 직접 생성하지 않습니다. ComfyUI 서버에 작업을 넣고, 서버가 만든 파일을 그 자리에서 읽어 보여 줍니다 (복사하지 않습니다).
화면 왼쪽에 메뉴가 셋 있습니다.
(노드 팩을 설치해 주는 ComfyUI-Manager와는 이름만 같은 다른 프로그램입니다.)

- **새 작업**: 생성 단계입니다. 위쪽 탭의 이미지 → 시나리오 → 영상을 ComfyUI API로 순서대로 실행합니다
- **작업 이력**: 이 프로그램으로 실행한 작업의 기록입니다 (언제, 어느 단계, 성공·실패, 프롬프트, 결과)
- **보관함**: 서버 결과 폴더(ComfyUI의 `output`)의 이미지와 영상을, 만든 워크플로우와 프롬프트와 함께 보여 줍니다. ComfyUI가 꺼져 있어도 됩니다

오른쪽 위에는 ComfyUI 연결 상태(점이 초록색이면 연결됨, 빨간색이면 연결 안 됨)와 톱니바퀴 버튼이 있습니다. 톱니바퀴를 누르면 설정이 열리고, 서버 연결, 서버 결과 폴더, VRAM 비우기, ComfyUI 재시작이 그 안에 있습니다.

## 작업 이력

이미지 생성, 시나리오 생성, 영상 생성을 실행할 때마다 한 줄씩 남습니다 (최신순, 화면에는 최근 300건). 실패하거나 중단한 작업도 남고, 실행 중인 작업은 맨 위에 보입니다.

- 줄마다 단계, 결과(완료 / 오류 / 중단됨), 시각, 걸린 시간, 입력한 내용(이미지 프롬프트, 시나리오 폴더와 연출 방향, 영상 워크플로우), 오류 내용, 저장된 경로가 나옵니다. 긴 글은 누르면 전부 펼쳐집니다
- 결과 파일이 서버 결과 폴더에서 보이면 썸네일이 붙고, 누르면 보관함과 같은 상세 화면이 열립니다 (나중에 이름을 바꾸거나 지운 파일은 썸네일이 나오지 않습니다)
- `새 작업으로 불러오기`: 그 작업의 입력을 새 작업 화면에 다시 넣습니다. 이미지 작업은 프롬프트·크기·seed와 만든 이미지를, 시나리오와 영상 작업은 그 시나리오 폴더를 불러옵니다
- **연결**: 작업끼리, 작업과 보관함 파일이 서로 이어져 있습니다. 영상 작업에는 쓴 시나리오와 시작 이미지가, 시나리오 작업에는 시작 이미지와 그 시나리오로 만든 영상이,
  이미지 작업에는 그 이미지로 만든 시나리오와 영상이 줄 아래에 나옵니다. 파일 이름을 누르면 보관함의 그 파일이 열리고, 시나리오 이름을 누르면 새 작업으로 불러옵니다
- 단계와 결과로 걸러 볼 수 있습니다

기록은 `data\manager.db`에 저장됩니다 (예전 `data\history.json`은 처음 켤 때 한 번 옮겨 오고 `history.json.imported`로 이름이 바뀝니다).
이 기능을 넣기 전에 실행한 작업은 기록에 없습니다. ComfyUI 화면에서 직접 돌린 작업도 여기에는 남지 않고 보관함에만 보입니다.
보관함에서 파일 이름을 바꾸면 연결은 따라가고, 보관함에서 지우면 그 작업의 줄은 남고 파일만 빠집니다. 탐색기에서 직접 바꾸거나 지운 파일은 연결이 끊깁니다.

## 보관함

- **파일 확인**: 이미지나 영상을 끌어다 놓으면 그것을 만든 워크플로우 이름과 프롬프트(구간이 여러 개면 전부), 네거티브, 모델·LoRA, seed, 샘플러 설정이 나옵니다
- **목록**: 서버 결과 폴더 전체를 읽어 썸네일로 보여 줍니다. 정렬은 최신순 / 오래된순 / **워크플로우별** / 이름순, 워크플로우 이름을 누르면 그것만 걸러 보고, 프롬프트 내용으로 검색할 수 있습니다
- **이 파일을 만든 작업**: 이 프로그램으로 만든 파일은 상세 화면에 그 작업(단계, 결과, 시각, 프롬프트)과 연결된 것(시작 이미지, 시나리오, 만든 영상)이 나옵니다.
  `새 작업으로 불러오기`와 `작업 이력에서 보기`가 있고, 목록에서는 그런 파일에 `작업 이력` 표시가 붙습니다
- **즐겨찾기 · 태그 · 메모**: 상세 화면에서 별을 눌러 즐겨찾기를 하고, 태그(쉼표로 구분)와 메모를 적어 저장합니다. 목록에서는 `즐겨찾기만`으로 거르고, 태그 이름을 눌러 그 태그만 봅니다.
  검색은 태그와 메모 내용도 찾습니다. 파일 이름을 바꿔도 따라가고, 파일을 지우면 같이 지워집니다. 파일에 써 넣는 것이 아니라 `data\manager.db`에만 저장됩니다
- **첫 프레임 / 마지막 프레임**: 영상을 눌러 상세 화면을 열면 영상 아래에 첫 프레임과 마지막 프레임이 그림으로 나옵니다. 누르면 원래 크기로 열리고 `PNG 받기`로 저장할 수 있습니다 (마지막 프레임은 이어지는 영상의 시작 이미지로 쓸 수 있습니다). 한 번 뽑은 프레임은 `data\frames\`에 남아 다음에는 바로 나옵니다
- **이름 변경 / 삭제**: 목록의 파일을 눌러 연 상세 화면에서 합니다. 이름 변경은 같은 폴더 안에서 이름만 바꾸고 확장자는 그대로 둡니다. 삭제는 `삭제`를 누른 뒤 `정말 삭제`를 한 번 더 눌러야 하고, 서버 결과 폴더에서 파일을 바로 지우므로 되돌릴 수 없습니다 (휴지통으로 가지 않습니다). 영상은 옆에 같이 저장된 미리보기 PNG도 함께 바꾸거나 지웁니다. 끌어다 놓아 확인한 파일에는 이 버튼이 없습니다
- **여러 개 선택해서 삭제**: 목록에서 각 파일 그림의 오른쪽 아래 네모를 눌러 고릅니다 (Shift를 누르고 누르면 앞서 누른 것부터 거기까지 한꺼번에). 하나라도 고르면 목록 위에 줄이 나타나고, `보이는 것 전체 선택`, `선택 해제`, `선택한 파일 삭제`가 있습니다. 삭제는 한 번 누르면 개수와 함께 확인을 묻고 한 번 더 눌러야 실행합니다. 하나씩 지울 때와 같이 서버 결과 폴더에서 바로 지워지고 되돌릴 수 없으며, 영상은 미리보기 PNG도 함께 지웁니다. 지우지 못한 파일(다른 프로그램이 쓰는 중 등)은 선택된 채로 남고 이유가 표시됩니다
- **워크플로우 JSON 받기 / 서버 workflow 폴더에 저장**: 파일에 들어 있는 워크플로우를 꺼냅니다. `서버 workflow 폴더에 저장`을 하면 연결된 ComfyUI 서버의 워크플로우 폴더에 저장되어 그 ComfyUI의 워크플로우 목록에 그 이름으로 나타납니다. 같은 이름이 이미 있으면 저장하지 않습니다 (영상을 ComfyUI에 끌어다 놓으면 "Unsaved Workflow"로 열리는 것을 대신하는 방법)

정보는 ComfyUI가 파일 안에 넣어 둔 메타데이터에서 읽습니다 (PNG, WebP/JPEG, MP4/WebM/MKV).

| 표시 | 뜻 |
|---|---|
| 워크플로우 이름 | 이 프로그램으로 만든 파일은 작업 기록에 남은 워크플로우 이름. 그 밖의 파일은 서버의 워크플로우 폴더에 있는 파일과 ID가 같거나 노드 구성이 같으면 그 파일 이름 (노드 구성으로 맞춘 것은 추정이라 다른 워크플로우일 수 있습니다) |
| `미등록 (모델명)` | 서버의 워크플로우 폴더에 같은 워크플로우가 없음. 저장하면 다음부터 그 이름으로 묶입니다 |
| `메타데이터 없음` | ComfyUI 정보가 없는 파일 (내려받은 영상, 메타데이터 저장을 끈 경우) |
| "실행 중에 … 노드가 쓴 프롬프트" | Qwen 같은 노드가 실행 중에 만든 글은 파일에 남지 않습니다. 대신 그 노드에 준 지시문을 보여 줍니다 |

Video Combine이 영상 옆에 같이 저장하는 미리보기 PNG는 기본으로 숨깁니다.

파일을 매번 분석하지는 않습니다. 목록에 쓰는 정보(워크플로우, 프롬프트 검색용 글, 크기, 길이)는 파일마다 한 번 읽어 `data\manager.db`(SQLite)에 저장해 두고,
보관함을 열 때는 폴더의 파일 이름·크기·수정 시각만 확인해서 새로 생겼거나 바뀐 파일만 다시 읽습니다. 없어진 파일은 목록에서 빠집니다.
썸네일(`data\thumbs\`)과 영상의 첫·마지막 프레임(`data\frames\`)도 한 번 만들면 다시 쓰고, 상세 화면만 그 파일 하나를 열 때마다 다시 읽습니다.
목록 정보는 서버 결과 폴더마다 따로 저장되어, 다른 서버의 폴더로 바꿨다가 돌아와도 다시 읽지 않습니다.

`data\manager.db`에는 다시 만들 수 있는 것(목록 정보)과 다시 만들 수 없는 것(작업 이력, 작업과 파일의 연결, 즐겨찾기·태그·메모)이 같이 들어 있습니다.
이 파일을 지우면 뒤의 것은 사라지니 백업하려면 이 파일을 복사해 두세요. `thumbs\`, `frames\`, `dropped\`는 지워도 다시 만들어집니다.

## 생성

직접 생성하지는 않고, 단계마다 ComfyUI API에 작업을 넣고 결과를 받아 옵니다.

1. **이미지**: 고른 이미지 워크플로우(기본은 z-image turbo)로 영상의 첫 프레임을 만듭니다 (가지고 있는 이미지를 올려도 됩니다)
2. **시나리오**: Qwen이 이미지를 보고 이어지는 영상을 구간 프롬프트 6개로 씁니다 (화면에서 고칠 수 있습니다)
3. **영상**: 시작 이미지와 구간 프롬프트를 고른 영상 워크플로우(기본은 Wan 2.2 SVI)에 넣어 영상을 만듭니다

## 실행

1. ComfyUI를 먼저 켭니다 (`Start_ComfyUI_L40S.bat`)
2. `tools\ComfyUI-Manager\Start_ComfyUI_Manager.bat` 실행 (보관함만 쓸 때는 ComfyUI 없이 이것만 실행해도 됩니다)
3. 브라우저에서 `http://127.0.0.1:8288` (다른 PC에서는 `http://<서버 IP>:8288`)

추가로 설치할 파이썬 패키지는 없습니다 (ComfyUI에 들어 있는 aiohttp, Pillow, PyAV만 씁니다).

### ComfyUI 서버 주소

설정(오른쪽 위 톱니바퀴)의 `ComfyUI 서버` 목록에서 전에 연결한 주소를 고르면 그 서버로 바뀝니다. 처음 쓰는 주소는 그 아래 칸에 넣고 `연결`을 누릅니다. 연결에 성공한 주소는 목록에 남습니다 (최근 15개, `data\settings.json`).

- 이 PC의 ComfyUI: `http://127.0.0.1:8188`
- 다른 서버의 ComfyUI: `http://<서버 IP>:8188` (서버의 ComfyUI가 `--listen 0.0.0.0`으로 켜져 있어야 합니다. `Start_ComfyUI_L40S.bat`은 그렇게 되어 있습니다)

바꾼 주소는 `data\settings.json`에 저장되어 다음에 켤 때도 그대로 쓰입니다. 실행 옵션 `--comfy`를 주면 그것이 우선합니다.

### 서버 결과 폴더

ComfyUI 서버가 결과를 저장하는 폴더를, 이 프로그램이 도는 PC에서 보이는 경로로 지정한 것입니다. 이 프로그램은 그 폴더를 읽기만 하고 결과를 다른 곳으로 복사하지 않습니다.
보관함이 이 폴더를 읽고, 작업이 끝나면 서버가 만든 파일을 이 폴더에서 찾아 작업 이력에 연결하고, 시나리오 폴더(`prompts.json`, 시작 이미지)도 여기에 만들어집니다.

설정(오른쪽 위 톱니바퀴)의 `폴더 선택…`을 누르면 폴더를 고르는 창이 뜹니다. 드라이브부터 눌러 들어가 `이 폴더 선택`을 누릅니다. 경로를 직접 적고 Enter를 눌러도 됩니다.
전에 쓴 폴더는 `폴더 선택…` 위의 목록에서 바로 고를 수 있습니다 (최근 15개).

- 예: 서버의 `E:\ComfyUI`가 이 PC에 `V:`로 연결되어 있고 서버가 `E:\ComfyUI\output`에 저장하면 `V:\output`을 지정합니다
- 그 위 폴더(`V:\`)를 골라도 됩니다. 서버가 알려 준 출력 폴더 경로와 맞춰 그 안의 `V:\output`을 찾아 씁니다
- 폴더는 ComfyUI 주소마다 따로 기억합니다. 서버를 바꾸면 그 서버에 지정해 둔 폴더로 바뀝니다 (`data\settings.json`의 `result_dirs`)
- `자동으로 찾기`: 지정을 지웁니다. ComfyUI가 이 PC에서 돌고 있으면 ComfyUI를 켤 때 준 출력 폴더(`--output-directory`)를, 다른 서버면 그 서버의 출력 폴더가 연결된 네트워크 드라이브를 찾아 씁니다
  (공유 이름이 출력 폴더까지 가는 길의 폴더 이름 `ComfyUI`나 드라이브 이름 `E`, `E$`와 같아야 찾습니다). 지정한 적이 없으면 이 방식으로 동작합니다
- 지정도 없고 찾지도 못하면 설정에 `서버 결과 폴더를 찾지 못했습니다`라고 나옵니다. 생성은 되고 미리보기도 나오지만, 결과가 보관함에 나오지 않고 작업 이력에 썸네일이 붙지 않습니다
  (이때 시나리오 폴더는 이 PC의 `ComfyUI-Easy-Install\output`에 만들어집니다)

만든 파일의 경로는 이 PC에서 보는 경로(서버 결과 폴더 안의 경로, 예: `V:\output\webapp\zimage_….png`)로 표시합니다.
서버 결과 폴더를 찾지 못해 이 PC에서 볼 수 없을 때만 ComfyUI가 저장한 서버 쪽 경로를 대신 보여 줍니다.
작업이 끝났는데 파일이 지정한 폴더에서 보이지 않으면 그 사실을 알려 줍니다 (폴더를 잘못 지정한 경우).

`config.json`의 `output_dir`이나 실행 옵션 `--output-dir`로 폴더를 주면 그것으로 고정되고 화면에서는 바꿀 수 없습니다.

이 프로그램에는 로그인이 없습니다. 페이지에 들어올 수 있는 사람은 누구나 서버 주소와 서버 결과 폴더를 바꾸고, 이 PC의 폴더 이름을 보고, 보관함의 파일 이름을 바꾸거나 지울 수 있으니, 그러면 곤란한 망에서는 `host`를 `127.0.0.1`로 두세요.

## 새 작업 화면

단계마다 위쪽에 탭이 따로 있습니다. 시나리오 탭과 영상 탭 맨 위에는 앞 단계에서 넘어온 것(시작 이미지, 시나리오)이 표시됩니다.

- **이미지**: 워크플로우를 고르고 프롬프트, 크기, seed(0이면 랜덤)를 정한 뒤 `이미지 생성`. 크기를 `워크플로우에 적힌 크기 그대로`로 두거나 steps를 비워 두면 워크플로우에 적힌 값을 씁니다. 여러 장 만들면 아래 썸네일에서 쓸 것을 고릅니다
- **시나리오**: 연출 방향(선택), 구간 수, 분석 방법과 모델을 고르고 `시나리오 생성`. 오른쪽에 구간별 프롬프트가 나오고 고친 뒤 `시나리오 저장`
- **영상**: 워크플로우를 고르고 `영상 생성`. 구간이 끝날 때마다 미리보기가 추가되고 마지막에 최종 영상이 맨 위에 표시됩니다
- 위쪽 `한 번에 실행`은 현재 입력값으로 세 단계를 이어서 돌립니다. `중단`은 실행 중인 ComfyUI 작업을 멈춥니다

### 분석 방법

| 방법 | 쓰는 것 | 비고 |
|---|---|---|
| Qwen GGUF 직접 호출 (기본) | `Shorts Qwen GGUF Vision` 노드 (`templates/scenario_gguf.api.json`) | QwenVL-Mod의 GGUF 모델을 프리셋·채팅 규약 없이 부릅니다. Mod와 ShortsRemake 노드가 필요합니다 |
| Qwen Chat | ComfyUI-QwenVL-Mod의 채팅 엔드포인트 (`/qwenvl/chat`) | 같은 모델이지만 채팅은 워크플로우 조수 역할이라 글이 짧게 나옵니다 |
| QwenVL 노드 | 원본 ComfyUI-QwenVL 노드 (`templates/scenario_qwenvl.api.json`) | 기본 Qwen3-VL-8B-Instruct |
| 직접 작성 | 모델 없음 | 빈 칸 6개를 만들어 직접 씁니다 |

모델 목록에는 서버에 실제로 받아 둔 모델만 나옵니다. 노드는 받지 않은 모델까지 전부 목록에 넣지만, 이 프로그램은 ComfyUI에 `models\LLM` 폴더의 파일을 물어(`/models/LLM`)
그 안에 있는 것만 남깁니다: GGUF는 같은 이름의 `.gguf` 파일이 있는 것, 나머지는 모델 이름과 같은 폴더에 가중치 파일(`.safetensors`, `.bin`)이 있는 것.
받아 둔 것이 하나도 없으면 목록에 그렇게 표시됩니다. ComfyUI가 그 폴더를 알려 주지 못하면(구버전 등) 거르지 않고 전부 보여 줍니다. 모델을 새로 넣은 뒤에는 1분쯤 지나야 목록에 나옵니다.

`프롬프트 분량`이 `자세히`면 구간마다 시작 자세, 동작 순서, 표정, 옷·머리 움직임, 카메라, 끝 자세를 쓰게 하는 지시문(구간당 90~130단어)을,
`보통`이면 짧은 지시문(40~70단어)을 씁니다. Qwen Chat에는 적용되지 않습니다.
같은 이미지와 모델(Qwen3.5-9B GGUF Q8)로 재 본 구간당 단어 수: Qwen Chat 약 20(영어 대신 한국어로 나와서 이후 지시문에 영어 지정을 추가함, 추가 후는 재지 않음), 직접 호출 + 보통 약 30, 직접 호출 + 자세히 약 85.

모델이 형식을 지키지 않아 구간을 못 읽으면 경고와 함께 답변 원문을 보여 줍니다. 원문을 보고 빈 칸을 채우거나 다시 생성하세요.

### 워크플로우 고르기

이미지 탭과 영상 탭의 워크플로우 목록은 **연결된 ComfyUI 서버에 저장된 워크플로우**(그 서버의 `ComfyUI\user\default\workflows`, 하위 폴더 포함)에서 읽어 옵니다.
이 프로그램이 도는 PC의 `workflow\` 폴더는 보지 않습니다 (이 PC의 ComfyUI에 연결했을 때는 그 ComfyUI의 워크플로우, 곧 이 PC의 것이 나옵니다).
서버에 저장된 워크플로우가 전부, 서버에 있는 이름과 순서 그대로 목록에 나옵니다 (`.json`만 떼고 보여 줍니다). 이 프로그램이 값을 넣을 곳이 없어 그 단계에서 실행할 수 없는 것은
이름 뒤에 `(이 단계에서 실행 불가)`가 붙고, 고르면 이유를 알려 줍니다. 모델이 서버에 있는지는 따지지 않습니다.
모델, LoRA, 샘플러 같은 값은 서버에 저장된 워크플로우에 적힌 그대로 실행합니다. 묶음 노드(서브그래프) 겉에 적어 둔 값도 그대로 따릅니다.
서버 주소를 바꾸면 그 서버의 워크플로우로 바뀌고, ComfyUI에 연결되지 않은 동안에는 목록을 읽지 못합니다.
ComfyUI에서 저장한 그대로의 파일(UI 형식, Get/Set 노드와 서브그래프 포함)도 되고, `Export (API)`로 저장한 `.api.json`도 됩니다.
어떤 워크플로우로 만들었는지는 결과 아래 줄, 영상 탭의 안내, 작업 이력의 각 줄, 보관함 상세 화면의 "이 파일을 만든 작업"에 표시됩니다.

| 단계 | 실행할 수 있는 조건 | 이 프로그램이 넣는 것 |
|---|---|---|
| 이미지 | 글로 이미지를 만드는 워크플로우: 프롬프트 노드(`CLIP Text Encode`)와 `Save Image`가 있고, 입력 이미지(`Load Image`)가 필요 없는 것 | 긍정 프롬프트, 크기(빈 latent 노드의 width/height), seed, 저장 파일 이름(`webapp/<워크플로우 이름>_<날짜>`). steps는 적었을 때만 |
| 영상 | 시작 이미지와 글로 영상을 만드는 워크플로우: `Load Image`, 프롬프트 노드, 영상 저장 노드(`Video Combine`, `Save Video`)가 있고 원본 영상이 필요 없는 것 | 시작 이미지, 구간 프롬프트. `매번 새 seed`를 켜면 seed도 |

- **긍정 / 부정 프롬프트**는 샘플러의 positive / negative 입력에서 거슬러 올라가 찾습니다. 부정 프롬프트, LoRA, 모델, 샘플러 설정은 워크플로우 파일 그대로입니다
- **구간**은 프롬프트 노드의 제목으로 알아봅니다: `1st_…`, `2nd_…` 또는 `구간 1 …`, `part 2 …`. 번호가 붙은 노드가 둘 이상이면 그 수만큼의 구간으로 보고, 아니면 프롬프트 1개짜리로 봅니다 (목록에 `구간 N개`로 표시)
- 시나리오 구간이 워크플로우 구간보다 적으면 마지막 프롬프트를 반복하고, 많으면 뒤쪽 프롬프트는 쓰지 않습니다 (영상 탭 안내에 표시)
- **시작 이미지**는 `Load Image`가 여럿이면 제목에 `1st`, `start`, `시작`이 들어간 것을 씁니다
- `서버에 없는 노드 있음`: 연결된 ComfyUI에 설치되지 않은 노드가 들어 있는 워크플로우입니다. 고르면 어떤 노드인지 나오고, 실행하면 ComfyUI가 거부할 수 있습니다
- `5_I2V_6seg_from_prompts`처럼 `prompts.json`을 노드로 읽는 워크플로우는 그 노드 대신 값을 직접 넣고, 구간 수만큼만 실행합니다
- 서버의 ComfyUI에서 워크플로우를 고쳐 저장하면 다음 실행부터 반영됩니다. 새로 저장한 워크플로우는 페이지를 새로 고치면 목록에 나옵니다

영상 탭의 `워크플로우 설정`을 펼치면 그 워크플로우에 있는 숫자 설정(구간별 초, Width/Height, 스텝 등 INT/Float 상수 노드)을 이번 실행에만 바꿀 수 있습니다.
`시작 이미지 비율에 맞춤`을 켜면 제목이 `Width`, `Height`인 상수가 있을 때 긴 변은 유지하고 시작 이미지 비율로 맞춥니다.

처음에 골라져 있는 것은 `config.json`의 `image_workflow`(이미지, 기본 `image_z_image_turbo.json`)와 `svi_workflow`(영상)에 적힌 이름의 서버 워크플로우입니다. 서버에 그 이름이 없으면 실행할 수 있는 첫 번째 것이 골라집니다. 마지막에 고른 것은 브라우저가 기억합니다.
SVI 워크플로우를 변환 대신 `Export (API)`로 저장한 파일로 쓰려면 `templates/video_svi.api.json`으로 넣어 두세요. 이 파일이 있으면 그것을 씁니다.

변환이 ComfyUI와 같은지는 서버에서 직접 만든 결과 파일로 확인했습니다 (파일 안에 워크플로우와 ComfyUI가 실제로 실행한 내용이 같이 들어 있어, 워크플로우를 변환한 것과 대조할 수 있습니다): `image_z_image_turbo`와 SVI v3.5 계열은 완전히 일치합니다. 실제로 돌려 본 것은 `image_z_image_turbo`이고, 나머지는 값이 맞는 노드에 들어가는 것까지만 확인했습니다.

## ComfyUI 재시작

설정의 `ComfyUI 재시작`은 연결된 ComfyUI를 다시 시작합니다 (한 번 누르면 확인을 묻고, 한 번 더 눌러야 실행). 다른 서버의 ComfyUI도 됩니다.

- ComfyUI 자체에는 재시작 기능이 없어서, 그 서버에 설치된 ComfyUI-Manager 노드 팩의 재시작 주소(`/manager/reboot`)를 부릅니다. 그 노드 팩이 없거나 `security_level`이 `strong`이면 안 됩니다
- 켤 때와 같은 실행 옵션으로 다시 시작합니다. 실행 파일(`Start_ComfyUI_L40S.bat`)을 다시 읽지는 않으므로, bat의 옵션을 바꿨을 때는 서버에서 창을 닫고 bat으로 직접 켜야 합니다
- 실행 중이던 작업과 대기열은 사라집니다. 이 프로그램에서 실행 중인 작업이 있으면 먼저 중단해야 합니다
- ComfyUI가 응답하지 않을 만큼 멈춘 상태에서는 쓸 수 없습니다 (요청을 받을 수 있어야 재시작합니다)
- 다시 연결되기까지 1~2분 걸리고, 연결 표시가 초록색으로 돌아오면 끝난 것입니다

## VRAM

단계가 바뀔 때 이전 단계 모델을 내립니다 (`/free`, Qwen Chat은 `/qwenvl/chat/unload`). 같은 단계를 반복할 때는 모델을 그대로 둡니다.
ComfyUI UI에서 다른 작업을 같이 돌리면 이 순서가 깨지니 영상 단계 중에는 피하세요. 설정의 `VRAM 비우기` 버튼으로 직접 내릴 수도 있습니다.

## 저장 위치

- 생성 이미지: `output/webapp/zimage_<날짜>_NNNNN_.png`
- 시나리오: `output/<날짜_시간>_<이름>_prompts/` 안에 `prompts.json`, `reference.png`(시작 이미지), `model_answer.txt`(모델 답변 원문)
  - `prompts.json`은 Shorts 워크플로우(5번 등)의 Fanout / Reference Loader 노드가 읽는 형식과 같습니다
- 영상: 워크플로우의 저장 노드가 정한 곳 (SVI는 `output/Video/wanvideo_<날짜>_…mp4`)
- 시작 이미지는 영상 단계 전에 ComfyUI `input/webapp/`으로 복사됩니다

## 오프라인 서버에 옮길 것

`tools\ComfyUI-Manager\` 폴더. 워크플로우는 연결된 ComfyUI 서버에 저장된 것을 쓰므로 따로 옮길 파일이 없습니다.
