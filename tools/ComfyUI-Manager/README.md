# ComfyUI-Manager: 이미지·영상 생성 관리

ComfyUI와 따로 도는 작은 웹 서버입니다. 이 프로그램은 직접 생성하지 않습니다. ComfyUI 서버에 작업을 넣고, 서버가 만든 파일을 그 자리에서 읽어 보여 줍니다 (복사하지 않습니다).
화면 왼쪽에 메뉴가 여섯 있습니다.
(노드 팩을 설치해 주는 ComfyUI-Manager와는 이름만 같은 다른 프로그램입니다.)

- **새 작업**: 생성 단계입니다. 위쪽 탭의 이미지 → 시나리오 → 영상을 ComfyUI API로 순서대로 실행합니다
- **작업 이력**: 새 작업에서 영상까지 만든 뒤 `기록`을 눌러 남긴 작업입니다. 하나를 열면 그때의 이미지와 프롬프트가 들어간 새 작업 화면이 됩니다
- **시나리오**: 만든 시나리오(시작 이미지와 구간 프롬프트)를 모아 보고, 새 작업에서 열거나 이름을 바꾸거나 지웁니다
- **보관함**: 서버 결과 폴더(ComfyUI의 `output`)의 이미지와 영상을, 만든 워크플로우와 프롬프트와 함께 보여 줍니다. ComfyUI가 꺼져 있어도 됩니다
- **파일 확인**: 갖고 있는 이미지나 영상 파일을 넣으면 그것을 만든 워크플로우와 프롬프트를 보여 줍니다. 내려받은 모델이 있는 폴더를 적으면 종류를 알아보고 모델 폴더의 맞는 자리로 보냅니다
- **모델**: 서버 모델 폴더(Easy-Install의 `model`)의 파일을 폴더별로 크기·날짜와 함께 보여 주고, 보관함에서 쓴 횟수를 세고, 이름을 바꾸거나 지웁니다

오른쪽 위에는 ComfyUI 연결 상태(점이 초록색이면 연결됨, 빨간색이면 연결 안 됨)와 톱니바퀴 버튼이 있습니다. 톱니바퀴를 누르면 설정이 열리고, 서버 연결, 서버 결과 폴더, VRAM 비우기, ComfyUI 재시작이 그 안에 있습니다.

## 작업 이력

실행한 것을 자동으로 쌓는 목록이 아니라, 완성한 작업 중 남기기로 한 것만 모아 두는 곳입니다.

1. 새 작업에서 이미지 → 시나리오 → 영상까지 만듭니다. 영상 생성이 끝나면 영상 탭의 `영상 생성` 옆에 있는 `기록` 버튼이 켜집니다
2. `기록`을 누르면 그 작업이 작업 이력에 남습니다. 남는 것: 시작 이미지와 그것을 만든 프롬프트·워크플로우·seed, 영상에 쓴 구간 프롬프트 전부(시나리오), 연출 방향 같은 시나리오 설정, 영상 워크플로우와 그 설정, 최종 영상
3. 작업 이력에서 기록한 작업을 누르면 **새 작업과 같은 화면**이 그때의 내용으로 채워져 열립니다 (영상 탭에 그 영상이 보이고, 이미지·시나리오 탭에 쓴 이미지와 프롬프트가 들어 있습니다)
4. 그 화면에서 다시 실행하면 seed가 달라져 다른 결과가 나오는 새 작업이 됩니다. 프롬프트나 워크플로우를 고쳐서 돌려도 됩니다. 끝나면 `기록`이 다시 켜지고, 누르면 별개의 기록으로 남습니다

- 기록은 그때의 내용을 따로 보관합니다. 나중에 시나리오 폴더의 프롬프트를 고치거나 다시 실행해도 이미 남긴 기록의 내용은 바뀌지 않고, 기록을 열 때 시나리오 폴더가 기록할 때의 프롬프트로 되돌려집니다
- 왼쪽 `새 작업`을 누르면 기록에서 연 화면을 비우고 빈 새 작업으로 돌아갑니다
- 카드의 `기록 삭제`는 그 기록만 지웁니다 (한 번 더 눌러 확인). 이미지와 영상 파일은 그대로 둡니다
- 영상을 만들고 `기록`을 누르지 않으면 작업 이력에는 남지 않습니다. 파일은 보관함에 있고, 보관함에서 그 파일을 열면 만든 작업의 프롬프트를 볼 수 있습니다
- 시작 이미지를 이 프로그램으로 만들지 않고 올린 경우에는 이미지 프롬프트 없이 기록됩니다
- 보관함에서 최종 영상의 이름을 바꿔도 기록은 따라갑니다. 영상을 지웠으면 카드에 시작 이미지가 대신 나오고, 기록을 열면 프롬프트와 설정은 그대로 있습니다

기록은 `data\manager.db`에 저장됩니다. 실행한 작업 하나하나(이미지·시나리오·영상)도 내부적으로는 남겨 두는데, 목록으로 보여 주지는 않고 보관함에서 "이 파일을 만든 작업"을 보여 주는 데 씁니다.

## 시나리오

시나리오는 시작 이미지 한 장과 그 뒤를 잇는 구간 프롬프트 묶음입니다. 새 작업의 시나리오 탭에서 만든 것, `저장할 이름`으로 따로 저장한 것,
보관함의 영상에서 `새 작업에서 사용`으로 만든 것이 모두 여기에 모입니다.

- **목록**: 시작 이미지, 이름, 구간 수(빈 칸이 있으면 그 수), 요약, 고친 때, 그 시나리오로 기록한 작업 수가 나옵니다. 이름과 프롬프트 내용으로 검색할 수 있습니다
- **보기**: 카드를 누르면 시작 이미지와 구간 프롬프트 전부, 공통 프롬프트, 네거티브가 나옵니다 (프롬프트마다 복사 버튼)
- **새 작업에서 열기**: 그 시나리오와 시작 이미지를 새 작업의 시나리오 탭에 불러옵니다. 프롬프트를 고치거나 영상 탭에서 바로 실행하면 됩니다
- **이름 변경**: 폴더 이름이 바뀌고, 그 시나리오로 만든 작업 이력의 기록도 새 이름을 따라갑니다
- **삭제**: 하나씩(보기 화면에서) 또는 카드의 네모로 여러 개를 골라 한 번에 지웁니다. 한 번 더 눌러 확인해야 하고 되돌릴 수 없습니다. 프롬프트와 시작 이미지 사본이 지워지고, 만든 영상과 작업 이력의 기록은 남습니다
  (기록은 프롬프트를 따로 갖고 있어서, 지운 뒤에도 기록을 열면 시나리오가 다시 만들어집니다)

### 시나리오 폴더

시나리오는 서버 결과 폴더 안이 아니라 그 옆의 최상위 폴더 `scenario`에 따로 둡니다. 서버 결과 폴더가 `V:\output`(서버의 `E:\ComfyUI\output`)이면
`V:\scenario`(서버의 `E:\ComfyUI\scenario`)이고, `input`, `output`, `temp`와 같은 높이입니다. 시나리오마다 `scenario\<이름>_prompts\` 폴더에
`prompts.json`, `reference.png`(시작 이미지), `comfyui_prompts.txt`, `model_answer.txt`가 들어 있습니다.

- 예전 버전이 서버 결과 폴더 안에 만든 시나리오 폴더(`output\<…>_prompts`)는 이 프로그램을 켠 뒤 처음 쓸 때 `scenario` 폴더로 옮겨집니다.
  이 프로그램이 만든 것만 옮기고, Shorts 워크플로우의 노드가 만든 `<영상>_prompts` 폴더는 그 워크플로우가 `output`에서 읽으므로 그대로 둡니다
- 그래서 보관함에는 시나리오의 시작 이미지(`reference.png`)가 더 이상 섞여 나오지 않습니다
- 다른 곳에 두려면 `config.json`의 `scenario_dir`에 전체 경로를 적습니다

## 파일 확인

왼쪽 `파일 확인` 메뉴에 이미지나 영상을 끌어다 놓거나 `파일 선택`으로 고르면, 그것을 만든 워크플로우 이름과 프롬프트(구간이 여러 개면 전부), 네거티브, 모델·LoRA, seed, 샘플러 설정이 나옵니다.
서버 결과 폴더에 없는 파일(다른 곳에서 받은 파일 등)도 됩니다. 끌어다 놓기는 이 메뉴가 열려 있을 때만 받습니다.

### 받은 모델 보내기

내려받은 모델을 모델 폴더(`model`)의 맞는 하위 폴더로 옮기는 곳입니다.

1. `모델을 받은 폴더`에 이 PC의 경로를 적고(처음에는 사용자의 `Downloads`, 그 뒤로는 마지막에 쓴 폴더) `모델 찾기`를 누릅니다. `폴더 선택…`으로 골라도 됩니다
2. 그 폴더와 하위 3단계까지의 모델 파일(`.safetensors`, `.gguf`, `.ckpt`, `.sft`, `.pt`, `.pth`)이 종류, 보낼 곳과 함께 나옵니다. 보낼 곳은 줄마다 바꿀 수 있고, `(보내지 않음)`으로 두면 그 파일은 건드리지 않습니다
3. 보낼 파일을 체크하고 `선택한 모델 보내기`를 누릅니다. 기본은 **이동**이고(같은 드라이브면 크기와 상관없이 바로 끝납니다), `원본 남기기`를 켜면 복사합니다. 진행률이 아래에 나오고 `중단`할 수 있습니다

- **종류는 파일 안에서 알아냅니다** (이름이 아니라): `.safetensors`는 머리말의 텐서 이름과 메타데이터로 LoRA / 체크포인트(모델+VAE·텍스트 인코더) / diffusion 모델 / VAE / 텍스트 인코더 / CLIP vision / ControlNet / 임베딩을 가리고, `.gguf`는 구조 이름(`wan`, `flux`, `ltxv` … 는 diffusion 모델, 그 밖은 텍스트 인코더)으로 가립니다. 머리말만 읽으므로 수십 GB 파일도 바로 나옵니다. 종류 아래에 그렇게 본 이유가 나옵니다
- `.ckpt`, `.pt`, `.pth`는 안전하게 열어 볼 수 없어 이름으로 판단합니다 (`vae`, `lora`, `esrgan` 등). 알아내지 못하면 `알 수 없음`으로 나오고 보낼 곳을 직접 골라야 합니다
- 보낼 곳: LoRA → `loras`, 체크포인트 → `checkpoints`, diffusion 모델 → `diffusion_models`(GGUF는 `unet`), VAE → `vae`, 텍스트 인코더 → `text_encoders`, CLIP vision → `clip_vision`, ControlNet → `controlnet`, 업스케일 모델 → `upscale_models` / `latent_upscale_models`. 모델 폴더에 그 폴더가 없으면 다음 후보(`unet` ↔ `diffusion_models`, `text_encoders` → `clip`)를 씁니다
- **들어 있던 폴더째 보냅니다** (`들어 있던 폴더째 보내기`, 기본으로 켜짐): 파일이 받은 폴더 안의 하위 폴더에 있었으면 그 폴더 구조가 보낼 곳 아래에 그대로 만들어집니다. 경로에 모델 폴더와 같은 이름의 폴더(`lora`, `loras`, `checkpoints`, `vae`, `models` …)가 있으면 그 뒤부터만 따라갑니다: `받은폴더\lora\HIGH\a.safetensors` → `loras\HIGH\a.safetensors`, `받은폴더\묶음\스타일\b.safetensors` → `loras\묶음\스타일\b.safetensors`. 받은 폴더 자체가 `…\lora\HIGH`여도 `HIGH`가 따라갑니다. 줄마다 `→ loras/HIGH/a.safetensors`처럼 도착할 자리가 나옵니다. 끄면 폴더 없이 보낼 곳 바로 아래로 갑니다
- 이동으로 비게 된 원래 폴더(`받은폴더\lora\HIGH` 등)는 함께 지워집니다. 다른 파일이 남아 있는 폴더와 받은 폴더 자체는 그대로 둡니다
- 종류를 파일에서 알아내지 못했어도 모델 폴더와 같은 이름의 폴더 안에 있었으면 그 폴더를 보낼 곳으로 제안합니다
- 받는 자리에 같은 이름의 파일이 이미 있으면 줄에 그렇게 표시되고, 보내도 **덮어쓰지 않고 건너뜁니다** (원본도 그대로 남습니다)
- 지금 모델 폴더에 있는 77개 파일로 맞춰 봤을 때 76개가 실제 있는 폴더와 같게 나왔습니다 (나머지 하나는 `diffusion_models`에 든 LoRA였습니다)

## 보관함

- **목록**: 서버 결과 폴더 전체를 읽어 썸네일로 보여 줍니다. 정렬은 최신순 / 오래된순 / 즐겨찾기 먼저 / **워크플로우별** / 이름순, 워크플로우 이름을 누르면 그것만 걸러 보고, 프롬프트 내용으로 검색할 수 있습니다
- **새 작업에서 사용**: 상세 화면의 이 버튼은 그 파일에 기록된 내용으로 새 작업을 엽니다. 준비하는 데 시간이 걸리면 끝날 때까지 `작업 중` 창이 화면을 덮습니다 (작업 이력에서 기록을 열 때도 같습니다). ComfyUI에서 직접 만든 파일이든 이 프로그램으로 만든 파일이든 됩니다
  - 영상: 영상에 들어 있는 구간 프롬프트(제목이 `1st_…`, `구간 1 …`인 순서대로)와 부정 프롬프트, 시작 이미지로 새 시나리오 폴더를 만들고 시나리오 탭을 엽니다. 프롬프트를 고친 뒤 영상 탭에서 실행하면 됩니다
  - 시작 이미지는 영상을 만들 때 쓴 입력 이미지가 서버에 남아 있으면 그것을, 없으면 영상의 첫 프레임을 씁니다 (어느 쪽인지 안내에 나옵니다)
  - 같은 워크플로우가 서버에 저장되어 있고 영상 단계에서 실행할 수 있으면 그것을 골라 줍니다. LoRA 같은 설정은 서버에 저장된 그 워크플로우의 지금 값이므로, 영상을 만들 때와 달라졌을 수 있습니다
  - 실행 중에 노드가 쓴 프롬프트(Qwen 등)는 파일에 남지 않아 그 구간은 빈 칸으로 옵니다
  - 이미지: 그 이미지를 시작 이미지로 넣고, 이미지 프롬프트와 워크플로우를 이미지 탭에 채웁니다
  - 프롬프트 정보가 없는 영상(내려받은 영상 등)에는 쓸 수 없습니다
- **이 파일을 만든 작업**: 이 프로그램으로 만든 파일은 상세 화면에 그 작업(단계, 결과, 시각, 프롬프트)과 연결된 것(시작 이미지, 시나리오, 만든 영상)이 나옵니다.
  목록에서는 그런 파일에 `작업 이력` 표시가 붙습니다
- **즐겨찾기 · 태그 · 메모**: 목록의 각 파일 그림 오른쪽 위에 있는 별(☆)을 누르면 파일을 열지 않고 즐겨찾기가 됩니다 (다시 누르면 해제, 상세 화면의 별도 같습니다). 태그(쉼표로 구분)와 메모는 상세 화면에서 적어 저장합니다.
  목록에서는 정렬을 `즐겨찾기 먼저`로 두면 즐겨찾기한 파일이 앞에 모이고(그 안에서는 최신순), `즐겨찾기만`으로 거르고, 태그 이름을 눌러 그 태그만 봅니다. 목록에서 별을 누른 뒤의 순서는 정렬을 다시 고르거나 `새로 고침`을 누르면 맞춰집니다.
  검색은 태그와 메모 내용도 찾습니다. 파일 이름을 바꿔도 따라가고, 파일을 지우면 같이 지워집니다. 파일에 써 넣는 것이 아니라 `data\manager.db`에만 저장됩니다
- **첫 프레임 / 마지막 프레임**: 영상을 눌러 상세 화면을 열면 영상 아래에 첫 프레임과 마지막 프레임이 그림으로 나옵니다. 누르면 원래 크기로 열리고 `PNG 받기`로 저장할 수 있습니다 (마지막 프레임은 이어지는 영상의 시작 이미지로 쓸 수 있습니다). 한 번 뽑은 프레임은 `data\frames\`에 남아 다음에는 바로 나옵니다
- **이름 변경 / 삭제**: 목록의 파일을 눌러 연 상세 화면에서 합니다. 이름 변경은 같은 폴더 안에서 이름만 바꾸고 확장자는 그대로 둡니다. 삭제는 `삭제`를 누른 뒤 `정말 삭제`를 한 번 더 눌러야 하고, 서버 결과 폴더에서 파일을 바로 지우므로 되돌릴 수 없습니다 (휴지통으로 가지 않습니다). 영상은 옆에 같이 저장된 미리보기 PNG도 함께 바꾸거나 지웁니다. 끌어다 놓아 확인한 파일에는 이 버튼이 없습니다
  - 상세 화면에서는 `‹ 이전` / `다음 ›`(키보드 ← →)으로 목록의 앞뒤 파일로 넘어가고, Delete 키가 `삭제` 버튼과 같습니다 (두 번 눌러야 지워집니다). 지우면 창이 닫히지 않고 목록의 다음 파일이 열려, 보면서 이어서 지울 수 있습니다. Esc는 닫기입니다
- **우클릭으로 삭제**: 목록의 파일에 마우스를 올리고 우클릭하면 그 자리에 `삭제` 버튼이 뜨고(지울 파일은 빨간 테두리), 그 버튼을 누르면 바로 지워집니다. 선택해 둔 파일 위에서 우클릭하면 선택한 것 전부가 대상입니다. 다른 곳을 누르거나 Esc를 누르면 지우지 않고 닫힙니다
- **여러 개 선택해서 삭제**: 목록에서 Ctrl을 누른 채 파일을 누르거나 각 파일 그림의 오른쪽 아래 네모를 눌러 고릅니다 (Shift를 누르고 누르면 앞서 누른 것부터 거기까지 한꺼번에). 하나라도 골라져 있는 동안에는 파일을 그냥 눌러도 열리지 않고 선택/해제가 됩니다 (Esc로 풀면 다시 열립니다). Ctrl+A는 보이는 것 전체 선택입니다. 고른 개수는 목록 위의 파일 수 옆에 나옵니다 (따로 줄이 생기지 않아 목록이 밀리지 않습니다). 삭제는 선택한 파일 위에서 우클릭하거나 Delete 키를 누르면 `선택한 N개 삭제` 버튼이 뜨고, 그 버튼을 누르거나 Delete(또는 Enter)를 한 번 더 누르면 실행합니다. 하나씩 지울 때와 같이 서버 결과 폴더에서 바로 지워지고 되돌릴 수 없으며, 영상은 미리보기 PNG도 함께 지웁니다. 지우지 못한 파일(다른 프로그램이 쓰는 중 등)은 선택된 채로 남고 이유가 표시됩니다
- **워크플로우 JSON 받기 / 서버 workflow 폴더에 저장**: 파일에 들어 있는 워크플로우를 꺼냅니다. `서버 workflow 폴더에 저장`을 하면 연결된 ComfyUI 서버의 워크플로우 폴더에 저장되어 그 ComfyUI의 워크플로우 목록에 그 이름으로 나타납니다. 같은 이름이 이미 있으면 저장하지 않습니다 (영상을 ComfyUI에 끌어다 놓으면 "Unsaved Workflow"로 열리는 것을 대신하는 방법)

정보는 ComfyUI가 파일 안에 넣어 둔 메타데이터에서 읽습니다 (PNG, WebP/JPEG, MP4/WebM/MKV).

| 표시 | 뜻 |
|---|---|
| 워크플로우 이름 | 이 프로그램으로 만든 파일은 작업 기록에 남은 워크플로우 이름. 그 밖의 파일은 서버의 워크플로우 폴더에 있는 파일과 ID가 같거나 노드 구성이 같으면 그 파일 이름 (노드 구성으로 맞춘 것은 추정이라 다른 워크플로우일 수 있습니다) |
| `미등록 (모델명)` | 서버의 워크플로우 폴더에 같은 워크플로우가 없음. 저장하면 다음부터 그 이름으로 묶입니다 |
| `메타데이터 없음` | ComfyUI 정보가 없는 파일 (내려받은 영상, 메타데이터 저장을 끈 경우) |
| "실행 중에 … 노드가 쓴 프롬프트" | Qwen 같은 노드가 실행 중에 만든 글은 파일에 남지 않습니다. 대신 그 노드에 준 지시문을 보여 줍니다 |

Video Combine이 영상 옆에 같이 저장하는 미리보기 PNG는 기본으로 숨깁니다.

파일을 매번 분석하지는 않습니다. 목록에 쓰는 정보(워크플로우, 프롬프트 검색용 글, 크기, 길이)는 파일마다 한 번 읽어 `data\manager.db`(SQLite)에 저장해 두고,
보관함을 열 때는 폴더의 파일 이름·크기·수정 시각만 확인해서 새로 생겼거나 바뀐 파일만 다시 읽습니다. 없어진 파일은 목록에서 빠집니다.
썸네일(`data\thumbs\`)과 영상의 첫·마지막 프레임(`data\frames\`)도 한 번 만들면 다시 쓰고, 상세 화면만 그 파일 하나를 열 때마다 다시 읽습니다.
목록 정보는 서버 결과 폴더마다 따로 저장되어, 다른 서버의 폴더로 바꿨다가 돌아와도 다시 읽지 않습니다.

`data\manager.db`에는 다시 만들 수 있는 것(목록 정보)과 다시 만들 수 없는 것(기록한 작업 이력, 실행한 작업과 파일의 연결, 즐겨찾기·태그·메모)이 같이 들어 있습니다.
이 파일을 지우면 뒤의 것은 사라지니 백업하려면 이 파일을 복사해 두세요. `thumbs\`, `frames\`, `dropped\`는 지워도 다시 만들어집니다.

## 모델

서버의 모델 폴더에 있는 파일을 정리하는 곳입니다. 파일 안을 읽지는 않고, 폴더와 파일 이름, 크기, 날짜만 봅니다.
파일 관리 프로그램처럼 창이 둘입니다: **왼쪽은 서버의 모델 폴더**(트리), **오른쪽은 이 PC의 아무 폴더**입니다. 한쪽에서 고른 것을 다른 쪽의 현재 폴더로 복사합니다.

- **왼쪽 (모델 폴더)**: 서버 결과 폴더 옆의 최상위 폴더 `model`입니다 (Easy-Install이 모델을 두는 곳. 서버 결과 폴더가 `V:\output`이면 `V:\model`). 그 폴더가 없으면 `ComfyUI\models`를 봅니다. 다른 곳이면 `config.json`의 `model_dir`에 전체 경로를 적습니다.
  창 머리에 모델 폴더 전체 용량이 나옵니다 (마우스를 올리면 드라이브의 남은 공간도). 폴더(`checkpoints`, `loras`, `unet` …)마다 파일 수와 합계 크기가 있고, 누르면 펼쳐지거나 접힙니다 (펼친 폴더는 브라우저가 기억합니다). 위의 검색 칸은 이 창의 파일 이름을 거르고, 정렬은 폴더 안 파일의 순서입니다 (이름순 / 큰 것부터 / 최신순 / 보관함에서 안 쓴 것부터). `put_…_here` 같은 자리 표시 파일은 뺍니다
- **오른쪽 (이 PC의 폴더)**: 위 칸에 경로를 적고 Enter, 또는 `폴더 선택…`으로 고릅니다. 비우면 드라이브 목록이고, `위로`는 위 폴더입니다. 폴더를 누르면 그 안이 펼쳐집니다 (펼칠 때 읽습니다). 마지막에 쓴 경로는 브라우저가 기억합니다. 네트워크 드라이브, USB 등 이 PC에서 보이는 곳이면 됩니다
- **고르기**: 파일을 누르면 선택됩니다 (Ctrl로 더하고, Shift로 범위, Ctrl+A로 그 창의 보이는 것 전체, Esc로 해제). 폴더는 네모를 누르거나 Ctrl이나 Shift를 누른 채 누르면 **안의 폴더와 파일까지 전부** 선택됩니다 (그냥 누르면 펼쳐집니다). 접혀 있던 폴더도 선택된 것이고, 펼치면 안의 것이 선택된 채로 나옵니다. 그렇게 고른 폴더는 복사하면 통째로, 지우면 안의 파일이 전부 지워집니다 (폴더 자체는 남습니다) 마지막에 누른 창이 테두리가 밝은 **쓰는 창**이고, 각 창에서 마지막에 누른 것이 있는 폴더가 그 창의 **현재 폴더**입니다 (왼쪽 테두리로 표시)
- **복사**: 한쪽에서 고르면 그 창의 선택 개수 옆에 `오른쪽 <폴더> 로 복사` / `왼쪽 <폴더> 로 복사` 버튼이 나옵니다. 누르면 다른 창의 현재 폴더로 복사합니다 (F5는 쓰는 창에서 다른 창으로). 폴더를 골랐으면 안의 것까지 통째로 복사합니다. 서버가 뒤에서 복사하고 아래에 진행률(복사한 양, 지금 복사하는 파일)이 나오며 `중단`할 수 있습니다 (중단하면 반쯤 복사된 파일은 지웁니다). **받는 쪽에 같은 이름이 이미 있으면 덮어쓰지 않고 건너뛰고** 그렇게 알려 줍니다. 한 번에 하나의 복사만 됩니다. 모델 폴더에서 내보내거나 모델 폴더로 들여오는 복사만 되고, 이 PC의 다른 두 폴더 사이는 안 됩니다. 이동은 없습니다 (복사한 뒤 원본을 지우세요)
- **보관함 사용**: 왼쪽 파일에 마우스를 올리면 크기·날짜와 함께, 보관함의 이미지·영상 중 그 모델(체크포인트, diffusion 모델, VAE, 텍스트 인코더, LoRA 등)로 만든 것의 수가 나옵니다. 파일에 기록된 모델 이름을 파일 이름으로 맞춰 셉니다. 정렬 `보관함에서 안 쓴 것부터`가 이 수를 씁니다 (보관함에서 지운 결과물은 세지 않고, 서버 결과 폴더가 아닌 곳의 결과물도 세지 않습니다)
- **ComfyUI 목록에 없음**: ComfyUI에 연결되어 있으면 ComfyUI가 모델 목록에 넣는 파일(`/models/<폴더>`)과 대조합니다. ComfyUI가 아는 폴더(`checkpoints`, `loras`, `pulid` 등)에 있는 모델 파일인데 ComfyUI의 어느 목록에도 없으면 이 표시가 붙습니다: ComfyUI가 그 폴더를 다른 경로로 알고 있거나(`extra_model_paths.yaml`에 없는 폴더), 읽지 않는 형식입니다. 커스텀 노드가 제 나름대로 읽는 폴더(`insightface` 등)는 ComfyUI가 모르는 폴더라 따지지 않습니다. 연결되지 않았으면 대조하지 않고 그렇게 표시합니다
- **이름 변경·삭제 (왼쪽만)**: 파일 위에서 우클릭하면 `삭제`와 `이름 변경` 버튼이 뜹니다. 이름 변경은 이름이 칸으로 바뀌고 Enter로 바꾸고 Esc로 그만둡니다 (확장자는 그대로, 같은 폴더 안에서만). 삭제는 보관함과 같습니다: 버튼을 누르면 바로 지워지고(되돌릴 수 없고 휴지통으로 가지 않습니다), 선택한 파일 위에서 우클릭하거나 Delete를 누르면 선택한 것 전부를 지웁니다. 폴더 자체는 지우지 않습니다 (폴더를 골라 지우면 안의 파일이 지워지고 빈 폴더가 남습니다). 오른쪽 창의 파일은 지우거나 이름을 바꾸지 않습니다. 지운 뒤 ComfyUI의 모델 목록은 ComfyUI가 폴더를 다시 읽을 때 반영됩니다
- **크기**: 이 메뉴는 화면 너비를 다 씁니다. 두 창 사이의 세로 줄을 끌면 너비가, 창 아래의 가로 손잡이를 끌면 높이가 바뀌고, 브라우저가 기억합니다
- 서버가 다른 PC일 때는 그 모델 폴더가 이 PC에서 보여야 합니다 (서버 결과 폴더와 같은 네트워크 드라이브). 폴더가 안 보이면 `모델 폴더가 없습니다`라고 나옵니다
- 로그인이 없으므로 (위 '서버 결과 폴더' 참고) 페이지에 들어올 수 있는 사람은 오른쪽 창으로 이 PC의 폴더와 파일 이름을 보고, 모델 폴더와 이 PC의 폴더 사이에 복사할 수 있습니다

## 생성

직접 생성하지는 않고, 단계마다 ComfyUI API에 작업을 넣고 결과를 받아 옵니다.

1. **이미지**: 고른 이미지 워크플로우(기본은 z-image turbo)로 영상의 첫 프레임을 만듭니다 (가지고 있는 이미지를 올려도 됩니다)
2. **시나리오**: Qwen이 이미지를 보고 이어지는 영상을 구간 프롬프트 6개로 씁니다 (화면에서 고칠 수 있습니다)
3. **영상**: 시작 이미지와 구간 프롬프트를 고른 영상 워크플로우(기본은 Wan 2.2 SVI)에 넣어 영상을 만듭니다

## 실행

1. ComfyUI를 먼저 켭니다 (`Start_ComfyUI_L40S.bat`)
2. `tools\ComfyUI-Manager\Start_ComfyUI_Manager.bat` 실행 (보관함만 쓸 때는 ComfyUI 없이 이것만 실행해도 됩니다). 명령 창에 로그가 나오고 브라우저에 페이지가 열립니다
3. 다른 PC에서는 `http://<서버 IP>:8288`

- **브라우저에서 페이지를 닫으면 10~30초 뒤에 프로그램이 스스로 꺼지고 명령 창도 닫힙니다** (`config.json`의 `close_with_page: true`, 기본값). 페이지를 새로 고치거나 다른 메뉴로 가는 것은 닫는 것이 아닙니다. 페이지가 여럿 열려 있으면 마지막 것이 닫힐 때 꺼집니다. 생성 단계나 모델 복사가 진행 중이면 끝날 때까지 기다렸다가 꺼집니다 (ComfyUI의 작업 자체는 이 프로그램이 꺼져도 계속됩니다). 페이지가 90초 안에 한 번도 열리지 않아도 꺼집니다
- 다른 PC에 페이지를 내주는 서버로 계속 켜 두려면 `config.json`의 `close_with_page`를 `false`로 바꿉니다. 그러면 명령 창을 닫을 때까지 돕니다
- 로그는 명령 창과 `tools\ComfyUI-Manager\data\manager.log`에 남습니다 (1 MB씩 3개까지). 시작하지 못하면(포트가 이미 쓰이는 등) 명령 창에 이유가 남고 아무 키나 누를 때까지 닫히지 않습니다

추가로 설치할 파이썬 패키지는 없습니다 (ComfyUI에 들어 있는 aiohttp, Pillow, PyAV만 씁니다).

### ComfyUI 서버 주소

설정(오른쪽 위 톱니바퀴)의 `ComfyUI 서버` 목록에서 전에 연결한 주소를 고르면 그 서버로 바뀝니다. 처음 쓰는 주소는 그 아래 칸에 넣고 `연결`을 누릅니다. 연결에 성공한 주소는 목록에 남습니다 (최근 15개, `data\settings.json`).

- 이 PC의 ComfyUI: `http://127.0.0.1:8188`
- 다른 서버의 ComfyUI: `http://<서버 IP>:8188` (서버의 ComfyUI가 `--listen 0.0.0.0`으로 켜져 있어야 합니다. `Start_ComfyUI_L40S.bat`은 그렇게 되어 있습니다)

바꾼 주소는 `data\settings.json`에 저장되어 다음에 켤 때도 그대로 쓰입니다. 실행 옵션 `--comfy`를 주면 그것이 우선합니다.

### 서버 결과 폴더

ComfyUI 서버가 결과를 저장하는 폴더를, 이 프로그램이 도는 PC에서 보이는 경로로 지정한 것입니다. 이 프로그램은 그 폴더를 읽기만 하고 결과를 다른 곳으로 복사하지 않습니다.
보관함이 이 폴더를 읽고, 작업이 끝나면 서버가 만든 파일을 이 폴더에서 찾아 그 작업에 연결합니다. 시나리오는 이 폴더 옆의 `scenario` 폴더에 둡니다 (위 '시나리오 폴더' 참고).

설정(오른쪽 위 톱니바퀴)의 `폴더 선택…`을 누르면 폴더를 고르는 창이 뜹니다. 드라이브부터 눌러 들어가 `이 폴더 선택`을 누릅니다. 경로를 직접 적고 Enter를 눌러도 됩니다.
전에 쓴 폴더는 `폴더 선택…` 위의 목록에서 바로 고를 수 있습니다 (최근 15개).

- 예: 서버의 `E:\ComfyUI`가 이 PC에 `V:`로 연결되어 있고 서버가 `E:\ComfyUI\output`에 저장하면 `V:\output`을 지정합니다
- 그 위 폴더(`V:\`)를 골라도 됩니다. 서버가 알려 준 출력 폴더 경로와 맞춰 그 안의 `V:\output`을 찾아 씁니다
- 폴더는 ComfyUI 주소마다 따로 기억합니다. 서버를 바꾸면 그 서버에 지정해 둔 폴더로 바뀝니다 (`data\settings.json`의 `result_dirs`)
- `자동으로 찾기`: 지정을 지웁니다. ComfyUI가 이 PC에서 돌고 있으면 ComfyUI를 켤 때 준 출력 폴더(`--output-directory`)를, 다른 서버면 그 서버의 출력 폴더가 연결된 네트워크 드라이브를 찾아 씁니다
  (공유 이름이 출력 폴더까지 가는 길의 폴더 이름 `ComfyUI`나 드라이브 이름 `E`, `E$`와 같아야 찾습니다). 지정한 적이 없으면 이 방식으로 동작합니다
- 지정도 없고 찾지도 못하면 설정에 `서버 결과 폴더를 찾지 못했습니다`라고 나옵니다. 생성은 되고 미리보기도 나오지만, 결과가 보관함에 나오지 않고 작업 이력에 썸네일이 붙지 않습니다
  (이때 시나리오는 이 PC의 `ComfyUI-Easy-Install\scenario`에 만들어집니다)

만든 파일의 경로는 이 PC에서 보는 경로(서버 결과 폴더 안의 경로, 예: `V:\output\webapp\zimage_….png`)로 표시합니다.
서버 결과 폴더를 찾지 못해 이 PC에서 볼 수 없을 때만 ComfyUI가 저장한 서버 쪽 경로를 대신 보여 줍니다.
작업이 끝났는데 파일이 지정한 폴더에서 보이지 않으면 그 사실을 알려 줍니다 (폴더를 잘못 지정한 경우).

`config.json`의 `output_dir`이나 실행 옵션 `--output-dir`로 폴더를 주면 그것으로 고정되고 화면에서는 바꿀 수 없습니다.

이 프로그램에는 로그인이 없습니다. 페이지에 들어올 수 있는 사람은 누구나 서버 주소와 서버 결과 폴더를 바꾸고, 이 PC의 폴더 이름을 보고, 보관함의 파일 이름을 바꾸거나 지울 수 있으니, 그러면 곤란한 망에서는 `host`를 `127.0.0.1`로 두세요.

## 새 작업 화면

단계마다 위쪽에 탭이 따로 있습니다. 시나리오 탭과 영상 탭 맨 위에는 앞 단계에서 넘어온 것(시작 이미지, 시나리오)이 표시됩니다.

- **이미지**: 워크플로우를 고르고 프롬프트, 크기, seed(0이면 랜덤)를 정한 뒤 `이미지 생성`. 크기를 `워크플로우에 적힌 크기 그대로`로 두거나 steps를 비워 두면 워크플로우에 적힌 값을 씁니다. 여러 장 만들면 아래 썸네일에서 쓸 것을 고릅니다
- **시나리오**: 연출 방향(선택), 구간 수, 분석 방법과 모델을 고르고 `시나리오 생성`. 오른쪽에 구간별 프롬프트가 나오고 고친 뒤 `시나리오 저장`
  - `저장할 이름` 칸에 이름을 적고 저장하면 그 이름의 시나리오(`scenario\<이름>_prompts`)로 저장됩니다. 이름을 그대로 두면 지금 시나리오에 덮어쓰고, 바꾸면 같은 시작 이미지를 가진 새 시나리오가 만들어지며 원래 것은 그대로 남습니다. 이후 단계는 새로 저장한 것으로 이어집니다
  - 이름의 공백은 `_`로 바뀌고, 파일 이름에 쓸 수 없는 문자와 마침표는 빠지며 40자까지입니다. 같은 이름의 시나리오가 이미 있으면 저장하지 않고 알려 줍니다
  - `저장된 시나리오 불러오기` 목록에 그 이름으로 나옵니다
- **영상**: 워크플로우를 고르고 `영상 생성`. 구간이 끝날 때마다 미리보기가 추가되고 마지막에 최종 영상이 맨 위에 표시됩니다
- 위쪽 `한 번에 실행`은 현재 입력값으로 세 단계를 이어서 돌립니다. `중단`은 실행 중인 ComfyUI 작업을 멈춥니다

모델이 형식을 지키지 않아 구간을 못 읽으면 경고와 함께 답변 원문을 보여 줍니다. 원문을 보고 빈 칸을 채우거나 다시 생성하세요.

### 워크플로우 고르기

이미지 탭과 영상 탭의 워크플로우 목록은 **연결된 ComfyUI 서버에 저장된 워크플로우**(그 서버의 `ComfyUI\user\default\workflows`, 하위 폴더 포함)에서 읽어 옵니다.
이 프로그램이 도는 PC의 `workflow\` 폴더는 보지 않습니다 (이 PC의 ComfyUI에 연결했을 때는 그 ComfyUI의 워크플로우, 곧 이 PC의 것이 나옵니다).
서버에 저장된 워크플로우가 전부, 서버에 있는 이름과 순서 그대로 목록에 나옵니다 (`.json`만 떼고 보여 줍니다). 이 프로그램이 값을 넣을 곳이 없어 그 단계에서 실행할 수 없는 것은
이름 뒤에 `(이 단계에서 실행 불가)`가 붙고, 고르면 이유를 알려 줍니다. 모델이 서버에 있는지는 따지지 않습니다.
모델, LoRA, 샘플러 같은 값은 서버에 저장된 워크플로우에 적힌 그대로 실행합니다. 묶음 노드(서브그래프) 겉에 적어 둔 값도 그대로 따릅니다.
서버 주소를 바꾸면 그 서버의 워크플로우로 바뀌고, ComfyUI에 연결되지 않은 동안에는 목록을 읽지 못합니다.
ComfyUI에서 저장한 그대로의 파일(UI 형식, Get/Set 노드와 서브그래프 포함)도 되고, `Export (API)`로 저장한 `.api.json`도 됩니다.
어떤 워크플로우로 만들었는지는 결과 아래 줄, 영상 탭의 안내, 작업 이력의 각 기록, 보관함 상세 화면의 "이 파일을 만든 작업"에 표시됩니다.

| 단계 | 실행할 수 있는 조건 | 이 프로그램이 넣는 것 |
|---|---|---|
| 이미지 | 글로 이미지를 만드는 워크플로우: 프롬프트 노드(`CLIP Text Encode`)와 `Save Image`가 있고, 입력 이미지(`Load Image`)가 필요 없는 것 | 긍정 프롬프트, 크기(빈 latent 노드의 width/height), seed, 저장 파일 이름(`webapp/<워크플로우 이름>_<날짜>`). steps는 적었을 때만 |
| 영상 | 시작 이미지와 글로 영상을 만드는 워크플로우: `Load Image`, 프롬프트 노드, 영상 저장 노드(`Video Combine`, `Save Video`)가 있고 원본 영상이 필요 없는 것 | 시작 이미지, 구간 프롬프트. `매번 새 seed`를 켜면 seed도 |

- **긍정 / 부정 프롬프트**는 샘플러의 positive / negative 입력에서 거슬러 올라가 찾습니다. 부정 프롬프트, LoRA, 모델, 샘플러 설정은 워크플로우 파일 그대로입니다
- **구간**은 프롬프트 노드의 제목으로 알아봅니다: `1st_…`, `2nd_…` 또는 `구간 1 …`, `part 2 …`. 번호가 붙은 노드가 둘 이상이면 그 수만큼의 구간으로 보고, 아니면 프롬프트 1개짜리로 봅니다 (목록에 `구간 N개`로 표시)
- 시나리오 구간이 워크플로우 구간보다 적으면 마지막 프롬프트를 반복하고, 많으면 뒤쪽 프롬프트는 쓰지 않습니다 (영상 탭 안내에 표시)
- **시작 이미지**는 `Load Image`가 여럿이면 제목에 `1st`, `start`, `시작`이 들어간 것을 씁니다
- `서버에 없는 노드 있음`: 연결된 ComfyUI에 설치되지 않은 노드가 들어 있는 워크플로우입니다. 고르면 어떤 노드인지 나오고, 실행하면 ComfyUI가 거부할 수 있습니다
- `5_I2V_6seg_from_prompts`처럼 `prompts.json`을 노드로 읽는 워크플로우는 그 노드 대신 값을 직접 넣고, 구간 수만큼만 실행합니다
- 서버의 ComfyUI에서 워크플로우를 고쳐 저장하면 다음 실행부터 반영됩니다. 새로 저장한 워크플로우는 페이지를 새로 고치면 목록에 나옵니다

영상 탭의 `워크플로우 설정`을 펼치면 그 워크플로우에 있는 숫자 설정(구간별 초, Width/Height, 스텝 등 INT/Float 상수 노드)을 이번 실행에만 바꿀 수 있습니다.
`시작 이미지 비율에 맞춤`을 켜면 제목이 `Width`, `Height`인 상수가 있을 때 긴 변은 유지하고 시작 이미지 비율로 맞춥니다.

처음에 골라져 있는 것은 `config.json`의 `image_workflow`(이미지, 기본 `image_z_image_turbo.json`)와 `svi_workflow`(영상)에 적힌 이름의 서버 워크플로우입니다. 서버에 그 이름이 없으면 실행할 수 있는 첫 번째 것이 골라집니다. 마지막에 고른 것은 브라우저가 기억합니다.
SVI 워크플로우를 변환 대신 `Export (API)`로 저장한 파일로 쓰려면 `templates/video_svi.api.json`으로 넣어 두세요. 이 파일이 있으면 그것을 씁니다.

변환이 ComfyUI와 같은지는 서버에서 직접 만든 결과 파일로 확인했습니다 (파일 안에 워크플로우와 ComfyUI가 실제로 실행한 내용이 같이 들어 있어, 워크플로우를 변환한 것과 대조할 수 있습니다): `image_z_image_turbo`와 SVI v3.5 계열은 완전히 일치합니다. 실제로 돌려 본 것은 `image_z_image_turbo`이고, 나머지는 값이 맞는 노드에 들어가는 것까지만 확인했습니다.

## ComfyUI 재시작

설정의 `ComfyUI 재시작`은 연결된 ComfyUI를 다시 시작합니다 (한 번 누르면 확인을 묻고, 한 번 더 눌러야 실행). 다른 서버의 ComfyUI도 됩니다.

- ComfyUI 자체에는 재시작 기능이 없어서, 그 서버에 설치된 ComfyUI-Manager 노드 팩의 재시작 주소(`/manager/reboot`)를 부릅니다. 그 노드 팩이 없거나 `security_level`이 `strong`이면 안 됩니다
- 켤 때와 같은 실행 옵션으로 다시 시작합니다. 실행 파일(`Start_ComfyUI_L40S.bat`)을 다시 읽지는 않으므로, bat의 옵션을 바꿨을 때는 서버에서 창을 닫고 bat으로 직접 켜야 합니다
- 실행 중이던 작업과 대기열은 사라집니다. 이 프로그램에서 실행 중인 작업이 있으면 먼저 중단해야 합니다
- ComfyUI가 응답하지 않을 만큼 멈춘 상태에서는 쓸 수 없습니다 (요청을 받을 수 있어야 재시작합니다)
- 다시 연결되기까지 1~2분 걸리고, 연결 표시가 초록색으로 돌아오면 끝난 것입니다

## VRAM

단계가 바뀔 때 이전 단계 모델을 내립니다 (`/free`, Qwen Chat은 `/qwenvl/chat/unload`). 같은 단계를 반복할 때는 모델을 그대로 둡니다.
ComfyUI UI에서 다른 작업을 같이 돌리면 이 순서가 깨지니 영상 단계 중에는 피하세요. 설정의 `VRAM 비우기` 버튼으로 직접 내릴 수도 있습니다.

## 저장 위치

- 생성 이미지: `output/webapp/zimage_<날짜>_NNNNN_.png`
- 시나리오: 서버 결과 폴더 옆의 `scenario/<날짜_시간>_<이름>_prompts/` 안에 `prompts.json`, `reference.png`(시작 이미지), `model_answer.txt`(모델 답변 원문)
  - `prompts.json`은 Shorts 워크플로우(5번 등)의 Fanout / Reference Loader 노드가 읽는 형식과 같습니다
- 영상: 워크플로우의 저장 노드가 정한 곳 (SVI는 `output/Video/wanvideo_<날짜>_…mp4`)
- 시작 이미지는 영상 단계 전에 ComfyUI `input/webapp/`으로 복사됩니다

## 설정 (`config.json`)

| 키 | 기본값 | 설명 |
|---|---|---|
| `host` / `port` | `0.0.0.0` / `8288` | 웹 프로그램 주소. 이 PC에서만 쓰려면 host를 `127.0.0.1`로 |
| `comfy_url` | `http://127.0.0.1:8188` | ComfyUI 주소 |
| `output_dir` | (빈 값) | 서버 결과 폴더를 고정할 때만 적습니다. 비우면 화면에서 지정한 폴더, 없으면 자동 (위 '서버 결과 폴더' 참고) |
| `scenario_dir` | (빈 값) | 시나리오를 두는 폴더. 비우면 서버 결과 폴더 옆의 `scenario` |
| `model_dir` | (빈 값) | 모델 메뉴가 보는 폴더. 비우면 서버 결과 폴더 옆의 `model`, 없으면 `ComfyUI\models` |
| `image_workflow` | `image_z_image_turbo.json` | 이미지 워크플로우 목록에서 처음에 골라져 있는 서버 워크플로우의 이름 |
| `svi_workflow` | `workflow/Wan2.2_…v3.5.json` | 영상 워크플로우 목록에서 처음에 골라져 있는 서버 워크플로우의 이름 (`workflow/`는 떼고 봅니다) |
| `i2v_api` | `workflow/5_I2V_6seg_from_prompts.api.json` | 예전 기록(`I2V 6구간`으로 실행한 작업)을 다시 불러올 때 쓰는 파일 |
| `close_with_page` | `true` | 브라우저에서 마지막 페이지를 닫은 뒤 스스로 꺼집니다. `false`면 명령 창을 닫을 때까지 돕니다 (다른 PC가 쓰는 서버) |

실행 옵션 `--host --port --comfy --output-dir --open --close-with-page`가 config.json보다 우선합니다.
이미지와 영상의 모델, 스텝, 샘플러는 서버에 저장된 워크플로우에서, QwenVL 노드 기본값은 `templates/scenario_qwenvl.api.json`에서 바꿉니다.

## 오프라인 서버에 옮길 것

`tools\ComfyUI-Manager\` 폴더. 워크플로우는 연결된 ComfyUI 서버에 저장된 것을 쓰므로 따로 옮길 파일이 없습니다.
모델과 커스텀 노드는 해당 워크플로우를 ComfyUI에서 돌릴 때와 같습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `app.py` | 웹 서버, 단계 실행, ComfyUI 통신 |
| `library.py` | 파일의 메타데이터 읽기 (워크플로우·프롬프트·모델), 결과 폴더 목록, 이름 변경·삭제, 영상의 첫·마지막 프레임 |
| `data/` | 화면에서 바꾼 설정(`settings.json`), 저장소(`manager.db`), 썸네일·프레임, 로그(`manager.log`) (git에 올리지 않음) |
| `Start_ComfyUI_Manager.bat` | 실행 파일: 브라우저에 페이지를 열고, 페이지를 닫으면 명령 창과 함께 꺼짐 |
| `models.py` | 모델 폴더의 목록, 보관함에서 쓴 횟수, 이름 변경·삭제, 이 PC의 폴더 읽기, 뒤에서 도는 복사·이동, 모델 파일의 종류 알아내기 |
| `store.py` | SQLite 저장소 (`data/manager.db`): 보관함 목록 정보, 기록한 작업 이력, 실행한 작업과 파일의 연결, 즐겨찾기·태그·메모 |
| `comfy_convert.py` | UI 워크플로우 JSON → API JSON 변환 |
| `static/index.html` | 화면 |
| `templates/*.api.json` | 이미지 생성 / QwenVL 노드 분석용 API 템플릿 |
